# Anomizer

Локальная программа для анонимизации видео: автоматически блюрит лица, меняет
голос и умеет обрезать фрагмент. Работает офлайн, модель детектора уже лежит в
проекте, ничего не отправляет в сеть.

## Возможности

- **Лица.** Детектор YuNet (предобученная модель OpenCV) находит лица в каждом
  кадре. Обучение и покадровая разметка не нужны. Есть гауссово размытие и
  пикселизация с регулируемой силой и запасом вокруг лица.
- **Голос.** Сдвиг тона от −12 до +12 полутонов без изменения длительности,
  громкость и полное отключение звука. Используется FFmpeg/Rubber Band;
  по умолчанию форманты тоже сдвигаются — это сильнее скрывает тембр.
- **Таймкоды эффектов.** Блюр и смена голоса включаются независимо внутри
  выбранных диапазонов. В промежутках остаётся оригинал. По умолчанию включены
  оба эффекта на всём видео. Зоны видны на таймлайне: **Б** — блюр, **Г** —
  голос.
- **Минимальный редактор.** Выбор начала и конца фрагмента, просмотр кадра,
  проигрывание выбранного диапазона со звуком (с учётом зон эффектов) и экспорт.
- **Экспорт.** H.264/AAC в MP4, без метаданных исходника. Исходный файл не
  изменяется.
- **Чересстрочное видео.** Файлы 1080i/AVCHD автоматически деинтерлейсятся
  внешним FFmpeg и в предпросмотре, и при экспорте. Обычные прогрессивные файлы
  по-прежнему читаются через OpenCV.
- **Локальность.** Никаких API, аккаунтов и облака. FFmpeg поставляется
  Python-пакетом `imageio-ffmpeg`, системный FFmpeg не обязателен.

## Запуск

Нужен Python 3.10+ и Tkinter (в Debian/Ubuntu: `sudo apt install python3-tk`).

```bash
./run.sh
```

Скрипт сам создаст `.venv` и поставит зависимости. Вручную:

```bash
python3 -m venv --system-site-packages .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python app.py
```

Модель `models/face_detection_yunet_2023mar.onnx` уже лежит в проекте. Если её
нет, программа попробует скачать её один раз. Если скачать не удалось, есть
резервный детектор Хаара из OpenCV (хуже видит профиль).

### Веб-интерфейс

Тот же движок можно открыть в браузере — Tkinter для этого не нужен:

```bash
./run_web.sh
```

Скрипт при необходимости создаст `.venv`, поставит `fastapi`/`uvicorn` и
запустит сервер. Браузер откроется сам; адрес выглядит как
`http://127.0.0.1:8765/#<код>`. Код после `#` — локальный токен доступа: он не
передаётся на сервер в URL и не уходит в сеть. Если браузер не открылся,
скопируйте адрес из терминала. Полезные параметры: `--no-browser`,
`--port 8765` (`0` — выбрать свободный порт), `--temp-dir PATH`, `--token`
(скрытый, для скриптов).

Сервер слушает только `127.0.0.1`, проверяет `Host`/`Origin`, использует
HttpOnly-cookie сессии и защитный заголовок для изменяющих запросов. Наружу
ничего не отправляется. Загруженные через браузер файлы временные: они
удаляются при закрытии источника и остановке сервера. Исходник не изменяется.

## Готовые сборки

В `dist/` лежат переносимые архивы: Python, FFmpeg, модель и все зависимости
внутри, устанавливать ничего не нужно.

- `Anomizer-0.1.0-linux-x86_64.tar.gz` — desktop;
- `Anomizer-Web-0.1.0-linux-x86_64.tar.gz` — веб-интерфейс;
- `Anomizer-0.1.0-windows-x86_64.zip` — desktop;
- `Anomizer-Web-0.1.0-windows-x86_64.zip` — веб-интерфейс;
- `SHA256SUMS` — контрольные суммы.

Linux:

```bash
tar -xzf Anomizer-0.1.0-linux-x86_64.tar.gz
./Anomizer/Anomizer                 # desktop
# или
tar -xzf Anomizer-Web-0.1.0-linux-x86_64.tar.gz
./Anomizer-Web/anomizer-web         # веб-интерфейс
```

Windows: распакуйте zip и запустите `Anomizer\Anomizer.exe` либо
`Anomizer-Web\anomizer-web.exe` (удобнее — двойной щелчок по
`Anomizer-Web.bat`). Сборки не содержат установщика и не требуют прав
администратора.

PyInstaller не умеет кросс-компиляцию: Linux собирается на Linux командой
`./build_tools/build_linux.sh`, Windows — на Windows командой
`powershell -ExecutionPolicy Bypass -File .\build_tools\build_windows.ps1`.
Windows-артефакты в этом репозитории собраны и проверены в Wine, а не на
физической Windows-машине. Веб-интерфейс в Windows-сборке проверен полностью,
включая загрузку, детекцию, предпросмотр и экспорт. В desktop-версии Windows
предпросмотр звука требует `ffplay` в `PATH`; если его нет, звук доступен в
веб-интерфейсе или в готовом MP4 после экспорта.

## Как пользоваться

1. **Открыть видео…** — выбрать файл.
2. В панели **Лица** включить блюр, выбрать метод и силу.
3. В панели **Голос** задать сдвиг тона. `−3` полутона — заметно ниже,
   `+3` — выше. Галочка «Сохранять тембр» делает голос естественнее, но менее
   анонимным.
4. Тянуть по таймлайну или ввести **с** и **по** в секундах. Кнопки
   «= текущий» берут позицию плейхеда.
5. **Диапазоны эффектов…** — задать, где именно работают блюр и голос. В
   таблице можно менять начало/конец, независимо включать «Блюр» и «Голос»,
   добавлять, удалять и делить диапазон по плейхеду кнопкой «Разделить».
   Время вводится как секунды, `MM:SS` или `HH:MM:SS`; запятая и точка
   равнозначны. Изменения применяются сразу после выхода из поля или Enter.
   «Готово» закрывает окно, «Отмена»/Esc — без несохранённых правок; при
   неверном таймкоде «Готово» не закроет окно, пока ошибка не исправлена.
6. **Экспорт MP4…** — сохранить результат. Прогресс и отмена есть в панели
   «Экспорт».

Предпросмотр показывает блюр и рамки и воспроизводит обработанный звук с
учётом диапазонов. Если в системе нет рабочего аудиовыхода, видео всё равно
играет, а рядом с галочкой «Звук» появляется надпись «звук: недоступен».
Звук при экспорте не зависит от предпросмотра.

### Если предпросмотр молчит

Приложение сначала пытается отдать PCM в `pw-play` (PipeWire), затем в `aplay`
(ALSA), затем — напрямую в ALSA/Pulse средствами FFmpeg. Проверить вручную:

```bash
# PipeWire
pw-play /usr/share/sounds/alsa/Front_Center.wav
# ALSA
aplay /usr/share/sounds/alsa/Front_Center.wav
```

В Debian/Ubuntu обычно достаточно `sudo apt install alsa-utils` (для PipeWire —
пакет `pipewire-bin`). Можно задать свою команду, которая читает сырой
`s16le`, 48 кГц, stereo PCM со stdin:

```bash
ANOMIZER_AUDIO_PLAYER="pw-play -a --rate 48000 --channels 2 --format s16 -" ./run.sh
```

Если звук не нужен, снимите галочку «Звук» — экспорт это не затрагивает.

## CLI

Для пакетной обработки:

```bash
.venv/bin/python -m anomizer.cli input.mp4 -o output.mp4 \
  --start 12.5 --end 47.0 \
  --method pixelate --strength 4 \
  --voice -3.5
```

Отдельные зоны эффектов (время — абсолютное время исходного видео):

```bash
.venv/bin/python -m anomizer.cli input.mp4 -o output.mp4 \
  --blur-range 0 12.5 --blur-range 30.0 47.0 \
  --voice-range 12.5 30.0 --voice-range 47.0 1:02.0 \
  --voice -3
```

Диапазоны можно повторять; они автоматически обрезаются по фрагменту
`--start/--end`. Если флаг не указан, эффект работает на всём фрагменте, как
раньше. Чтобы полностью отключить эффект, используйте `--no-blur` или
`--voice 0`; в GUI — снимите галочки или удалите все диапазоны.

Полезные флаги:

```text
--no-blur / --method gaussian|pixelate / --strength 1..5 / --margin 0.22
--blur-range START END (можно повторять)
--voice -12..12 / --voice-range START END (можно повторять)
--preserve-formants / --volume 1.0 / --mute
--crf 20 / --preset veryfast / --detect-width 960
```

`--voice 0` отключает сдвиг тона, `--mute` убирает дорожку целиком.

## Тесты

```bash
.venv/bin/pip install pytest
.venv/bin/python -m pytest -q
```

Тесты проверяют разбор таймкодов, объединение интервалов, построение
аудиографа и реальный кусок пайплайна: тон 220 Гц должен остаться 220 Гц вне
зоны и понизиться примерно до 185 Гц внутри зоны (`--voice -3`), а длина
готового PCM — совпадать с длительностью фрагмента до сэмпла. Отдельные тесты
создают маленькое чересстрочное H.264-видео и проверяют, что полевое
расположение определяется по баннеру и флагам кадров `showinfo`, резервный
FFmpeg-ридер возвращает цветные кадры, перемотка (включая дробное начало)
даёт кадры, попиксельно совпадающие с полным декодированием, а экспорт
сохраняет точное число кадров и длительность звука.

## Чересстрочное видео

Anomizer сам определяет полевое порядковое расположение по баннеру FFmpeg
(`top first` / `bottom first`, включая варианты `top coded first (swapped)`).
Если баннер ничего не сообщает или говорит `progressive`, приложение
дополнительно спрашивает у FFmpeg флаги реально декодированных кадров
(`showinfo`) в начале и середине файла. Это надёжнее, чем судить по картинке
OpenCV: при неудачной конвертации он возвращает «успешный» кадр, который может
быть чёрным, мусорным или устаревшим буфером от предыдущего файла. Такие файлы
декодируются внешним FFmpeg с фильтром `yadif=deint=interlaced`: встроенный в
OpenCV swscale иногда отказывается конвертировать чересстрочный `yuv420p` в
`bgr24`. Это относится и к предпросмотру, и к экспорту; звук, таймкоды и зоны
эффектов не меняются. Прогрессивные файлы остаются на быстром пути OpenCV, а
`yadif` для них — точный no-op, поэтому резервный путь не портит картинку.

Автоматический деинтерлейсинг не заменяет конвертацию MTS: если контейнер не
читается, воспользуйтесь разделом ниже.

## MTS / AVCHD

MTS удобнее сначала сконвертировать в обычный MP4 — тогда работают все функции
без сюрпризов с аудиодорожкой и анаморфным кадром. Подойдёт любой конвертер,
например бесплатный **HandBrake**:

1. Открыть `.mts` в HandBrake.
2. Preset `Fast 1080p30` (или похожий), Container — `MP4`.
3. Video codec — `H.264`, Audio — `AAC`, включить `Web Optimized`.
4. Start.

Или системным FFmpeg:

```bash
ffmpeg -i input.mts \
  -vf "yadif=deint=interlaced,scale=trunc(iw*sar/2)*2:ih,setsar=1" \
  -c:v libx264 -crf 18 -preset veryfast \
  -c:a aac -b:a 192k -movflags +faststart \
  input.mp4
```

`yadif` аккуратно убирает интерлейс, если он есть, а `scale=...:ih,setsar=1`
превращает анаморфный кадр AVCHD (например, 1440×1080) в нормальные квадратные
пиксели. После этого открывайте `input.mp4` в Anomizer.

Встроенный в Python-пакет FFmpeg в текущей сборке MTS читает нестабильно,
поэтому приложение не притворяется, что всё в порядке: оно покажет ошибку и
попросит конвертировать файл. Если у вас есть рабочий системный FFmpeg, можно
попробовать запуск с `ANOMIZER_FFMPEG=/usr/bin/ffmpeg ./run.sh` — это
экспериментальный путь.

## Что под капотом

```text
OpenCV VideoCapture (прогрессивные файлы)
FFmpeg rawvideo + yadif (чересстрочные/сбойные)
        │
        ├── YuNet ONNX (детекция лиц) → трекер → Gaussian blur / pixelate
        │
        └── raw BGR кадры ──pipe──┐
                                  ├── FFmpeg: H.264 + Rubber Band + AAC → MP4
исходный файл ──trim audio───────┘
```

- Детекция в предпросмотре идёт на кадре, уменьшенном до 640 px по ширине;
  экспорт по умолчанию использует 960 px. Координаты масштабируются обратно.
- Простой IoU-трекер удерживает рамку 8 кадров, если детектор моргнул, чтобы
  лицо не «мигало» без блюра.
- Кадры передаются в FFmpeg через stdin как `bgr24`, поэтому не нужен
  гигантский промежуточный файл и не важен кодек, который умеет OpenCV.
- Для чересстрочных файлов кадры читает отдельный процесс FFmpeg (`yadif` →
  `rawvideo bgr24`). Перемотка перезапускает его на пару кадров раньше нужной
  позиции, чтобы `yadif` набрал соседние кадры, а лишние кадры отбрасываются.
  Поэтому первый кадр после перемотки не имеет артефакта на границе. stderr
  вычитывается отдельным потоком, чтобы FFmpeg не завис на заполненной трубе.
- Аудио обрезается и фильтруется в том же вызове FFmpeg. Цепочка:
  `rubberband=pitch=...:formant=shifted|preserved` (или резервная
  `asetrate` + `atempo`). Для частичного применения голоса один общий wet-фильтр
  обрабатывает всю дорожку, а `asplit`/`atrim`/`concat` собирают её из участков
  с оригиналом и с изменённым голосом. Границы режутся по общим округлённым
  сэмплам, а `apad` ограничен точной длительностью, поэтому звук и контейнер не
  удлиняются.
- Предпросмотр звука: FFmpeg отдаёт сырой PCM 48 кГц/stereo в `pw-play`
  (PipeWire) или `aplay` (ALSA); если их нет, используется прямой аудиовыход
  FFmpeg. Если аудиоустройство недоступно, предпросмотр продолжает работать без
  звука и показывает причину.
- Выход пишется во временный файл рядом с целевым и заменяет его только после
  успешного завершения. При отмене/ошибке временный файл удаляется.

## Без обучения и ручной разметки — да

Здесь нет ни обучения, ни покадровой разметки:

- YuNet — готовая модель, которая просто делает inference на CPU.
- Рамки лиц появляются автоматически в каждом кадре.
- Трекер только сглаживает пропуски детектора, а не требует участия человека.

Ограничения всё равно есть: детектор может пропустить лицо в профиль, сильно
повёрнутое, закрытое руками/маской, очень маленькое или размытое. Для
чувствительных материалов обязательно просмотрите результат. Можно увеличить
«запас вокруг лица», силу блюра и `--detect-width 1280`, но 100% гарантии
автоматическая детекция не даёт.

## Приватность: что важно понимать

- Исходник не изменяется: блюр применяется только в итоговом файле.
- Сдвиг тона и формантов затрудняет узнавание, но это не нейросетевая замена
  личности. Содержание речи и манера всё равно могут выдать человека.
- Внутри выбранных диапазонов применяется один сдвиг ко всей дорожке. Разные
  голоса сдвинутся на одну и ту же величину. Вне диапазонов голос остаётся
  оригинальным — это видно на таймлайне.
- Метаданные контейнера удаляются (`-map_metadata -1`), но визуальные детали
  фона, одежды, татуировок и т. п. не анонимизируются.

## Если нужен результат, а не свой код

- **Только лица:** утилита [`deface`](https://github.com/ORB-HD/deface) —
  автоматический блюр лиц в видео, ставится через pip.
- **Монтаж:** Kdenlive или Shotcut — если нужен полноценный редактор, а не
  обрезка.
- **Голос:** Audacity (Pitch Shift) или SoX; для пакетной обработки — FFmpeg с
  фильтром `rubberband`.
- **Детектор полегче/другой:** MediaPipe Face Detection (меньше модель, но
  капризнее с Python 3.13), RetinaFace или YOLO-face (точнее, но тяжелее).
- **GUI тяжелее, но красивее:** PySide6/Qt. Здесь сознательно выбран Tkinter —
  он уже есть в Python и не тянет сотни мегабайт.

```text
tests/                  быстрые и интеграционные тесты
models/                 ONNX-модель YuNet
```
